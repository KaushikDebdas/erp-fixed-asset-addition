## §1 Module overview & setup

- [CONFIRMED] Login is via Single Sign-On: the user opens `erp.brac.net`, reaching a "Welcome to Single Sign On Page" with two options — **PIN + Password** login (for users without a BRAC Gmail id) or **Google Sign in** (for users with a BRAC Gmail id). (PDF p.4)
- [CONFIRMED] After SSO login the user lands on a dashboard with module tiles: HRM, ePMS, **FIXED ASSET**, MICROFINANCE, ACCOUNTING, My BRAC, My Desk, Careers Portal, eRecruitment, Performance Dashboard, HR Analytics Dashboard. Clicking **Fixed Asset** opens the module. (PDF p.5)
- [CONFIRMED] (live, staging, 2026-10-05) After login the ERP dashboard sometimes shows an announcement image popup. It is taller than a 768 px high window, so its × close button is above the visible area and cannot be clicked (system bug); clicking outside the popup closes it at every window size tried. Details: `automation/element_catalog/dashboard_page.md`.
- [CONFIRMED] The Fixed Asset module's top-level menu tabs are: Setup, Registration, Asset Profile, Asset Transaction, Asset Transfer, Single Challan, Asset Expenditure, Asset Depreciation, Asset Disposal, Report. (PDF p.5; MD doc section list)
- [CONFIRMED] Setup menu has three sub-items: **Manage Building**, **Manage Floor**, **Manage Room** — a hierarchy (one branch can have one or more Buildings; each Building has Floors; each Floor has Rooms) used to record an asset's physical location. (MD doc §1; PDF p.6-14)
- [CONFIRMED] Each of Manage Building / Manage Floor / Manage Room has a Create form with: Branch Name (dropdown, required), the parent level selector (Building for Floor; Building+Floor for Room), a Name field (required), Remarks (optional), Is Active (optional checkbox), plus Reset/Close/Save buttons showing a success toast on save. (PDF p.7-14)
- [CONFIRMED] The Fixed Asset Dashboard (landing page of the module) shows coloured tiles: Registration, Transaction, Transfer/Challan, Expenditure, Disposal, Depreciation, and a "Pending Approval" panel listing feature names with counts. (PDF p.6; flowchart legend)
- [INFERRED] The "Pending Approval" dashboard panel count likely corresponds to items awaiting the current user's approval across all the module's Approval List screens, though no explicit mapping is documented. (PDF p.6, image-derived)

## §2 Asset Registration

- [CONFIRMED] "Asset Registration means creating the official identity of a newly purchased asset in the ERP system." (MD doc §2) — the PDF similarly states registration is used when an asset is purchased from market as a spot purchase or received as a gift item. (PDF p.14)
- [CONFIRMED] **Asset Registration by AAQ** — the registration entry screen. Fields: Branch Name & Number*, Registration Type (fixed value "AAQ"), Registration Date (auto business date), Purchase Date* (date picker), Project Name & Number* (dropdown), Source of Fund (dropdown, optional), Note/Remarks (optional, max 100 chars), a radio choice **Spot Purchase** or **Gift Item** (required, pick one), Vendor/Supplier/Lessor Name* (dropdown; a "Create New Supplier" link exists but per the manual cannot actually be used pre-go-live because it routes to the live Procurement module), Vendor/Supplier/Lessor Ref Number/Contact/Address (auto-populated from the selected vendor), and per Asset Detail row: Asset Group*, Asset Category*, Asset Sub Category*, Asset Item Name* (dropdowns), Measurement Unit, Warranty End Date (optional), Asset Item Specification* (free text, e.g. colour/brand), Quantity*, Unit Price (TK.)*. (MD doc §2; PDF p.14-18)
- [CONFIRMED] Rows are added to a grid via **Add**; multiple asset items can be entered in one registration. Rows can be edited before save; **Draft** allows later edit/delete, **Submit** is final (locks editing) and shows "Asset registration(AAQ) Successfully!". (PDF p.18)
- [CONFIRMED] Output of Asset Registration by AAQ: a **Registration No.** is generated. (MD doc §2)
- [CONFIRMED] **Asset Registration List** — shows all registrations created by AAQ (Draft or Submitted); Draft ones can be reviewed/edited/submitted or deleted from here; filters include Organization Branch, Registration Type, Vendor/Supplier/Lessor Name, MRR Number, Registration Number, Project Name & Number, Status, Registration/Approve date ranges. (MD doc §2; PDF p.19-20)
- [CONFIRMED] **Asset Registration Approval List** — used to approve, reject or send back a submitted registration. Supports bulk approve via checkboxes, or opening one record to see full detail and Approve/Reject/Sendback with an optional comment (comment is mandatory in practice when rejecting per the flow). (MD doc §2; PDF p.21-23)
- [CONFIRMED] On **Approve**: (1) an Asset ID / Serial Number is generated, and (2) a Journal Voucher is auto-created: **Fixed Asset (Group-wise) — Dr., Supplier Payable – Capex — Cr.** The accountant must then make a manual Accounting-module journal to pay the supplier: **Supplier Payable – Capex — Dr., Cash/Bank — Cr.** (MD doc §2; PDF p.23-24, matches flowchart `diagrams.reg`)
- [CONFIRMED] Once registered/approved, the asset's **Asset Utilization Status becomes `IN_USE`** and Depreciation Charge begins. (PDF p.24)
- [CONFIRMED] **Offline Assets Receive** — used when an asset is transferred from an "Offline Branch" i.e. a branch running **Ascend.net** (a non-ERP legacy system) into an ERP branch; the ERP branch records it on receipt of a Debit Note from the Ascend.net branch. Fields include Branch Name*, Sending Branch* (an Ascend.net/non-ERP branch, e.g. "[HO - BDHO] Head Office" shown as the sending side in the example), Receiving Project*, Sending Project*, Receiving Date*, Asset Purchase Date*, Area Current Account Code*, Note/Remarks, Vendor/Supplier/Lessor details, and per-item fields including **Existing Asset ID*** (the ID from the old system), Total Unit Price/Cost*, Accumulated Depreciation*, Written Down Value, Comp. Sl No., Total Life Time (Months), Remaining Life Time (Months). (MD doc §2; PDF p.24-25)
- [CONFIRMED] **Offline Assets Receive List** — list of assets received this way (Draft/Submitted), filterable by Organization Branch, Project, Status, Vendor, Registration Number, date ranges. (MD doc §2; PDF p.25-26)
- [CONFIRMED] **Offline Assets Receive Approval List** — a separate approval screen (its own list, distinct from the ordinary Asset Registration Approval List) used specifically to approve receipt of assets coming from non-ERP (Ascend.net) branches. (MD doc §2; PDF p.26-27)
- [CONFIRMED] Only one named actor appears anywhere in any of the three sources: **"AAQ"**, in the screen name "Asset Registration by AAQ" — no other role/person name is defined (see §12, §14). (MD doc, PDF, consistent across both)
- [CONFIRMED] (live, staging, 2026-10-03) End-to-end registration flow verified by automation: **AAQ form > Draft > Asset Registration List (status DRAFT) > click Registration Number > Submit (status PENDING) > Approval List > click Registration Number (View popup) > Approve in popup > Asset Serial Number appears in the popup's Asset Serials tab.** One user can create and approve on staging. Full step table: `projects/fixedasset/e2e-flows/asset-registration-aaq.md`.
- [CONFIRMED] (live) Exact toasts: Draft `Asset registration(AAQ) drafted Successfully!`; Submit `Asset registration(AAQ) submitted Successfully!`; Approve `Asset registration approved successfully.`
- [CONFIRMED] (live, 2026-10-04) The 20,000 Taka minimum on an AAQ asset line is checked on the **Unit Price** (2 x 10,000 is rejected, 3 x 20,000 is accepted), not on Quantity x Unit Price. **Land is exempt** (a Unit Price of 1 Taka is accepted); Furniture, Building, Laptop and Desktop enforce it. Land and Building need a Measurement above zero: `Measurement must be greater than zero for this asset group`.
- [CONFIRMED] (live, 2026-10-04) Note/Remarks on the AAQ form shows the placeholder "Maximum 100 characters" but accepts 200 (`maxlength=200`). NEEDS_CLARIFICATION: which limit is intended.
- [CONFIRMED] (live, 2026-10-04) **Asset Registration List**: the Created By filter starts with the logged-in user and lists only that user's registrations; emptying it lists everyone's. Reset empties every filter (Created By too) and does not re-run the search. The grid is newest first and cannot be sorted by clicking a heading. The Registration Number link opens the Asset Registration View popup. The **MRR Number filter has no effect** (NEEDS_CLARIFICATION: is it meant to filter MRR registrations by Reference Number?).
- [CONFIRMED] (live, 2026-10-04) **Asset Registration Approval List**: the registration popup offers only **Approve** and **Close** (plus an optional Comment, 500 characters); no Reject or Sendback control exists on the page, although the PDF describes Approve/Reject/Sendback (NEEDS_CLARIFICATION: where are Reject and Sendback done, or are they not enabled on staging?). Approved rows lose their tick box and show Approved By and Approval Date. Created By is empty by default on this list (it is pre-filled on the Registration List).
- [CONFIRMED] (live) Validation toasts on Draft/Submit: `Please Select Purchase Date.`, `Please Select a supplier.`, `No Asset in List to perform operation`, `Please Select a Project.`; an asset line under 20,000 Taka total is rejected with `Total Unit Price/Cost of Fixed Asset cannot be lower than 20000 Taka.`

## §3 Asset Profile

- [CONFIRMED] After an asset is approved/registered, a Serial Number is generated and a full profile is created, with three sub-menus: **Asset Serial Global List**, **Generate Barcode**, **Asset in Pending Process List**. (MD doc §3; PDF p.28)
- [CONFIRMED] **Asset Serial Global List** shows the complete details of an asset across tabs: Details, Depreciation History, Revaluation History, Transaction History, Expenditure, Disposal Info, Attachment. Search filters include Organization Branch, Asset Serial, Asset Item Name, Registration Type, MRR Number, Asset Group/Category/Sub Category, Registration Date range, Asset Utilization Status, Project, Source of Fund, Employee PIN/Name, AAQ Type, Assign Status, Building/Floor/Room, Warranty Ends Within, Asset Disposal Type. (MD doc §3; PDF p.28-30)
- [CONFIRMED] On the asset Details tab the user can view dozens of fields (see §13) and can edit **Asset Utilization Status** (via a "Change" button — values include IN_USE, DAMAGE, STOLEN, BURNED, UNDER_REPAIR), **Source Of Fund**, **Measurement** and **Item** (each with its own "Change" button), **Attach File**, and **Note**; every other field is read-only. The manual (PDF p.31-33) lists only Utilization Status, Attach File and Note, so it is out of date: the live screen is the accurate source.
- [CONFIRMED] **Generate Barcode** — select one or more assets from a grid via checkbox, set a Print Quantity per row (or a "Default Print Quantity" applied via Set), click **Generate** to preview, then Print. (MD doc §3; PDF p.33-34)
- [CONFIRMED] **Asset in Pending Process List** — shows an asset that is currently mid-workflow in any process (e.g. submitted for registration approval but not yet approved, submitted for transfer to another branch but not yet approved, etc.), with columns Asset Serial, Project Name, Asset Item Name, Sub Category, Category Name, Group Name, Status (PENDING/DRAFT), Pending In Feature (names which screen it is pending in, e.g. "Asset Assign"). (MD doc §3; PDF p.35)
- [CONFIRMED] **Asset Serial Split** — used to split one asset into multiple parts/units. **Prerequisite: the asset's "measurement" must be defined first** — if missing, the asset must be edited to add the measurement before split is possible. **Logic: the "Split Into" field determines how many equal parts the (written-down) value is divided into** — example given: WDV 100 taka split into 2 parts → 50 + 50 = 100. (MD doc §3)
- [CONFIRMED] **Asset Serial Split Approval List** — approves split requests; output is a **new Asset ID / Serial** generated for the split-off asset. (MD doc §3)
- [CONFIRMED] (live, staging, 2026-10-03) The Asset Serial Split and Asset Serial Split Approval List screens exist and match the MD doc: the Approval List popup (`Asset Split View`) shows Split Into, Written Down Value and Accumulated Depreciation, and a grid of the new assets with equal Percentage (a split of a laptop into 20 gives 20 lines of 5). ## §4 Asset Transaction

- [CONFIRMED] Covers three operations on an already-registered asset: **Assign** (give responsibility of an unassigned asset to an employee), **Un-Assign** (remove responsibility from an employee), **Internal Movement** (change the asset's physical location/branch-building-floor-room without changing custody meaning). (MD doc §4; PDF p.36)
- [CONFIRMED] **Asset Assign**: search by Asset Serial (partial match works) — only assets with Assign Status = Unassigned appear; selecting one auto-fills its details. "Add to Grid" allows assigning multiple assets in one submission. In the "Assign To" section, search Employee by PIN or Name (partial match), select Building/Floor/Room, optional Note/Remarks. Draft is editable/deletable; Submit locks it and routes it to **Transaction Approval List** (or to **Transaction List** if saved as Draft). (MD doc §4; PDF p.36-39)
- [CONFIRMED] **Asset Un-Assign**: search either by Serial Number or by Employee PIN (radio choice) — only Assigned assets are listed. "Hand Over To" section records who physically receives the asset back (PIN, Project, Branch, Building/Floor/Room, Note). Multiple assets can be unassigned together via "Add to Grid." (MD doc §4; PDF p.39-42)
- [CONFIRMED] **Asset Internal Movement**: **prerequisite — the asset must already be Assigned; unassigned assets cannot use this screen.** Search by Serial or Employee PIN (same pattern). Moves the asset to a new Building/Floor/Room under "Internal Movement To." (MD doc §4; PDF p.42-44, confirmed by flowchart `diagrams.transaction` decision node "Asset currently assigned? No → Blocked — must be assigned first")
- [CONFIRMED] **Transaction List** — shows Draft/Submitted Assign/Un-Assign/Internal Movement transactions; Draft ones are editable here; transactions **Sent Back** during approval also reappear here for editing/resubmission. (MD doc §4; PDF p.44)
- [CONFIRMED] **Transaction Approval List** — approves/rejects/sends-back Assign, Un-Assign and Internal Movement requests together (one shared approval screen for all three transaction types), with filters by Transaction Type, Transaction Status, date range; supports Approve/Reject/Send Back per record with an optional comment. (MD doc §4; PDF p.44-48)
- [CONFIRMED] After Approve, the detailed record becomes read-only and shows Asset Serial, Item Name, Sub Category, Category, Project Name, Assign Status, Assigned Before Approval, Utilization Status. (PDF p.47)

- [CONFIRMED] (live, staging, 2026-10-03) The Asset Transaction menu has **six** links: Asset Assign, Asset Un Assign, Asset Internal Movement, Transaction List, Transaction Approval List and **Asset Assign Acknowledgement** (the last was missing from the original sources and is now documented below). Assign, Un Assign, Internal Movement, Transaction List, Transaction Approval List and Asset Assign Acknowledgement are all explored below.

## §12 Roles & approval pattern

- [CONFIRMED] **No named roles or permissions matrix is defined anywhere in any of the three sources.** The only named actor across all sources is **"AAQ"**, appearing solely as part of the screen name "Asset Registration by AAQ" (see §2) — it is not explained what AAQ stands for or whether it denotes a role, a process code, or something else.
- [CONFIRMED] A consistent **maker-checker (initiator/approver) pattern repeats across every module**: an initiator creates a record and either **Saves as Draft** (editable/deletable later) or **Submits** (locks it, routes to a separate "...Approval List" screen). A different user acting as approver opens the dedicated Approval List screen and can **Approve**, **Reject**, or **Send Back** (with an optional/sometimes-effectively-required comment field). Send Back returns the record to the initiator's own worklist (e.g. the Transaction List, or the originating Create/Draft screen) for correction and resubmission; Reject appears to terminate the request. This pattern recurs identically for: Asset Registration, Offline Assets Receive, Asset Assign/Un-Assign/Internal Movement (shared Transaction Approval List), Asset Shipment Challan, Asset Shipment itself, Asset Single Out Challan, Asset Serial Split, Asset Expense, Asset Addition from Inventory/Vendor, Asset Write Off, Asset Sale, and Offline Transfer. (MD doc, all sections; PDF, all approval-screen screenshots; flowchart, every diagram's Approve/Reject/Send Back decision diamond)
- [CONFIRMED] Bulk approval is supported on list-style approval screens via row checkboxes + a single **Approve** button at the bottom, in addition to opening an individual record's Details popup to Approve/Reject/Send Back with a comment one at a time. (PDF — Asset Registration Approval List, Transaction Approval List, Asset Expense Approval, Asset Addition Approval screens, Asset Sale Schedule Approval List, all show this dual pattern)
- [CONFIRMED] Some workflows have a **dual-approval structure** (two separate approval steps for one logical transfer): e.g. Asset Transfer requires both "Asset Shipment Challan Approval List" (approves the Challan) AND a separate "Asset Shipment Approval" (approves the Shipment as a whole, after the Challan is approved) before a Gate Pass can be generated. (MD doc §5; flowchart `diagrams.transfer`)

## Popup — "Asset Registration View" (opened by clicking a Registration Number link)
- **Container locator**: `page.locator("#commonModal")` (Bootstrap modal; header class `modal-header modal-header-style`, title `<h4>Asset Registration View</h4>`).
- **Close button**: `page.get_by_role("button", {name: "Close"})` (also an `×` icon button in the header, `aria-hidden`, not reliably targetable by role — use the visible "Close" button at the bottom of the modal instead).
- Two tabs, both inside the same modal, switched via Bootstrap tab links:
  - **Details tab** (default, `a[href="#tab_details"]` equivalent — captured as the default-active tab): shows, matching 1:1 what was entered at creation —
    - Asset Registration Details panel: Registration No., Registration Type, Registration Date, Source Of Fund, Spot Purchase / Gift Item (radio, shows which was picked), Branch Name, Project Name, Department, Purchase Date, Note/Remarks.
    - Vendor/Supplier/Lessor Details panel: Vendor/Supplier/Lessor Name, Vendor/Supplier/Lessor Number, Vendor/Supplier/Lessor Address, Vendor/Supplier/Lessor Contact Number.
    - Asset Details grid: columns SL, Asset Item Name, Item Specification, Asset Sub Category, Asset Category, Asset Group, Measurement, Measurement Unit, Quantity, Unit Price(TK), Total Price(TK), Warranty End Date.
  - **Asset Serials tab** (`page.locator('a[href="#tab_asset_serials"]')`): "Registered Asset Serials" grid — columns SL, Asset Serial, Asset Item Name, Sub Category Name, Category Name, Asset Group. **Before Approve, this grid is empty** ("No data available in table") — this is where the generated Asset Serial Number(s) would appear after a successful Approve, confirmed by table structure though not populated this session (Approve did not succeed — see Notes).
- Verified this session against Registration Number 757755: every field in the popup matched the data entered on the AAQ form (Project `[C04] Administratiion`, Spot Purchase selected, Purchase Date 20/09/2026 = Registration Date 20/09/2026, Note/Remarks text, Vendor `ACE IT` / `P008937` / address, Asset line `Cabinet Table` / `AUTOMATION_TEST-SPEC-FURN-001` / `Wooden Furniture` / `Furniture` / `Furniture and Fixture` / qty 1 / unit price 25000 / total 25000).
- The page-level Approve button (`#btnApprove`) is NOT inside this modal — it remains on the underlying Approval List page, visible/clickable while the modal is open or after closing it. The modal's own "Asset Serials" tab has no separate approve action of its own that was found this session.

## Verified 2026-10-04 (regression suite run on staging)
- Filters and ids are the same as the Registration List: Branch `#office`, Registration Type `#registrationType`, Vendor `#supplierName`, MRR Number `#referenceNo`, Registration Number `#registrationId`, Created By `#createdBy`, Approved By `#approvedBy`, Project `#projectId`, Department `#receivingDept`, Status `#status`, date filters `#registrationFromDate`, `#registrationToDate`, `#approveFromDate`, `#approveToDate`; Search; Reset `#reset`. Created By starts EMPTY on this page. Status offers `-Select Status-`, PENDING, APPROVED, REJECTED, SENDBACK (no DRAFT).
- Grid `#assetRegistrationList` columns: (tick box), SL, Registration Number, Registration Date, Reference Number, Registration Type, Branch Name (hidden), Project Name, Department Name, Created By, Status, Approved By, Approval Date, Attachment, Approve (hidden). Newest first. Paging and Records per page behave as on the Registration List.
- Header tick box (`name=post`) ticks every row that can be approved on the page; unticking clears them. Only PENDING rows have a tick box. A per-row quick Approve button (`singleApprove`) sits in the hidden Approve column.
- Page-level Approve `#btnApprove` with nothing ticked shows `You have to select a Registration first`. With rows ticked it approves them all and shows `Asset registration approved successfully.`
- Re-checked 2026-10-05 on a PENDING registration: the popup holds only the × button, **Approve** and **Close**, and the grid row only an **Approve** button; the words Reject and Sendback appear only as Status filter options. Reject cannot be automated on this screen.
- Popup `#commonModal`: the only action buttons are **Approve** (`#approve`) and **Close**. A Comment box `#comment` ("Leave comment here... Maximum 500 characters", 500 characters are kept) and `#commentDate` are present. **No Reject or Sendback control exists anywhere on the page** (checked in the whole DOM, visible or not).
- Approve with a comment works. After approval the row shows APPROVED, Approved By, Approval Date and has no tick box; the popup of an approved registration has no Approve button and an empty Comment box.
- The same account that created a registration can approve it.

## Notes — IMPORTANT: role/permission finding, and the Approve blocker (now tried with 2 different projects)
- **CORRECTION (2026-10-03): the blocker below was per-project, not branch-wide.** Sessions 1 and 2 used `[801] EHC` and `[C04] Administratiion`, which have no Area Current Account Code mapped for Head Office [BDHO]. With `[015] Microfinance (Dabi)` Approve succeeds (toast `Asset registration approved successfully.`) and the Asset Serial Number appears in the popup's Asset Serials tab. The "branch-wide gap" conclusion in the entries below was wrong; they are kept as the record of what was observed at the time.
- **The same single test account (`abushoaib.asik`) that created the AAQ registration could also see it in this Approval List and attempt to approve it.** No second role/login was required — this confirms the flow CAN be automated as a **single-role** flow for UI-navigation purposes.
- **Session 1** — Registration 757754, Project `[801] EHC`: clicking Approve returned toast `"No Area Current Account Code: This branch is not mapped with project : [801] EHC"`. Status stayed PENDING.
- **Session 2** — Registration 757755, Project `[C04] Administratiion` (deliberately chosen as a different, core-looking Head-Office administrative project to test whether a different project would be mapped): clicking Approve (`#btnApprove`, after selecting the row checkbox `#assetRegistration`) returned the toast `"No Area Current Account Code: This branch is not mapped with project : [C04] Administratiion"`. Status stayed PENDING. **Approve did NOT succeed this session either** — no Asset Serial/Asset ID was generated, the Asset Serials tab in the popup remained empty.
- Since two different projects (`[801] EHC` and `[C04] Administratiion`) produced the identical class of error against the same branch (`Head Office [ BDHO ]`), this looks like a **branch-wide staging data/configuration gap** (the Head Office branch may have no Area Current Account Code mapped to ANY project in this staging environment), not a per-project issue. This is DATA_REQUIRES_REVIEW, not a locator problem — the `#btnApprove` locator and the selection flow are both VERIFIED as correct; only the business outcome could not be observed.
- Recommendation for the Automation Engineer / test data owner: get BRAC staging's branch↔project accounting mapping fixed for Head Office [ BDHO ], or identify (from the account-code setup screens, not guessed) a project genuinely mapped to a current account code for this branch, then re-run Approve to capture the success toast text and the generated Asset Serial Number. Until then, the Approve step of the automation must be written against `#btnApprove` + the DATA_REQUIRES_REVIEW status and should not assert a hardcoded success message, since none has been observed.
- No Approve-comment/reason textbox was located in either session, because the Approve action never got past the account-code error to reveal one, if any exists. Treat as unexplored, not as `LOCATOR_REQUIRES_REVIEW`.
- Same SPA hash-routing caveat: reach this page via the left menu (`Registration` → `Asset Registration Approval List`), not direct `page.goto()`.

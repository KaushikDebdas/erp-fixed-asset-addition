## Verified 2026-10-04 (regression suite run on staging)
- Reset buttons: `#resetDetails` clears only the Asset Details block; `#resetEditButton` (footer) clears the whole form. This replaces the LOCATOR_REQUIRES_REVIEW note on row 24.
- Grid: `#assetDetailsTable`; delete a line with `button[name=deleteAction]`; a line appears about 2 s after Add; an empty grid shows "No data available in table"; Grand Total shows e.g. `50,000`. A long Item Specification is shown shortened (first 30 characters + `...more`).
- Minimum rule: **the 20,000 Taka minimum is checked on the Unit Price, not on Quantity x Unit Price** (2 x 10,000 rejected, 3 x 20,000 accepted). **Land is exempt** (Unit Price 1 accepted). Furniture, Building, Laptop and Desktop enforce it. Row 22 above says "total": that wording is not what the app does.
- Land and Building need a Measurement above zero, else Add shows `Measurement must be greater than zero for this asset group`. Furniture, Laptop and Desktop need none.
- Note/Remarks (`#remarks`) has `maxlength=200` although its placeholder says "Maximum 100 characters"; 200 characters are kept.
- Item search: "Desktop Computer" also lists "All In One Desktop Computer-> ...", so pick the option whose name starts with the wanted text.
- Auto-filled boxes (`#assetCategory`, `#assetSubCategory`, `#assetGroup`, `#uom`, `#depRate`, `#supplierNumber`, `#supplierAddress`) fill about 3 s after the pick; wait for a value before reading. `#supplierContactNo` stayed empty for vendor ACE IT.
- Gift Item (`#giftItem`) shows the same fields as Spot Purchase and validates in the same order: `Please Select Purchase Date.`, `Please Select a supplier.`, `No Asset in List to perform operation`. The 20,000 Taka unit-price minimum applies. Draft and Submit give the same toasts; the list shows DRAFT and PENDING. Approve for a Gift Item registration was verified on 2026-10-05 (the Gift furniture and land were approved from their popup, the Gift building and laptop together with ticked rows).
- Draft with a blank form gives `Please Select Purchase Date.` first; `Please Select a Project.` was not reachable from a blank form.

## Opening/editing an existing Draft record
From Asset Registration List, clicking a DRAFT row's Registration Number link opens the SAME form (heading changes to "Update Asset Registration By AAQ") pre-filled with the saved values, still showing the Draft / Submit / Reset buttons — so Submit can be clicked directly from there to move the record from DRAFT to PENDING. Confirmed this session: Registration Number **757755** was created as a Draft, reopened via its list-row link, and Submitted successfully (toast above), without re-entering any field.

## Notes
- This is an Angular/jQuery hybrid SPA using hash routing (`#!moduleName/action`). **Direct `page.goto()` to a hash URL does NOT reliably re-render the correct view** — it was observed to leave the previously-rendered page's DOM in place. Always navigate by clicking the actual sidebar menu link (`Registration` category, then the specific sub-link), never by constructing/loading the hash URL directly.
- The announcement popup (`#modals` / `#modals button[data-close-button]`, documented in `dashboard_page.md`) did not appear during either session — treat as conditional per existing `BasePage.close_popup_if_present()`.
- Business rule discovered: Purchase Date is effectively mandatory (validated on "Add" AND on "Draft"), even though the visual asterisk is easy to miss next to the info icon.
- Business rule discovered: a line's Unit Price × Quantity must total at least 20,000 Taka, else "Add" is rejected with a toast: "Total Unit Price/Cost of Fixed Asset cannot be lower than 20000 Taka."
- Business rule discovered (this session): **Draft validates the same required fields as Submit** — Purchase Date, Vendor/Supplier, and at least one Asset Details grid line are all mandatory before Draft will succeed. Toasts seen while discovering this, in order: "Please Select Purchase Date." → "Please Select a supplier." → "No Asset in List to perform operation." → success.
- Business rule discovered (this session): **"Purchase Date = Registration Date"** is satisfiable by reading `#registrationDate`'s value (auto-filled, e.g. `20/09/2026`) and picking the same day in the Purchase Date calendar popup (`#forUpdate` button opens it); both fields end up with the identical `dd/mm/yyyy` string.
- Test data used in session 1 (for traceability, not a fixture): Project `[801] EHC`, Spot Purchase, Note/Remarks `AUTOMATION_TEST registration note`, Vendor `ACE IT[P008937]`, Asset Item `Air Conditioner (Cassate Type)`, Item Specification `AUTOMATION_TEST-SPEC-001`, Quantity `1`, Unit Price `25000`, Purchase Date and Registration Date `20/09/2026`. Result: **Registration Number 757754**, Status PENDING after Submit.
- Test data used in session 2 (for traceability, not a fixture): Project `[C04] Administratiion` (chosen as an alternative to `[801] EHC`, which was blocked last session — see `asset_registration_approval_list.md` for the outcome), Spot Purchase, Note/Remarks `AUTOMATION_TEST registration note - project C04`, Vendor `ACE IT[P008937]`, Asset Item `Cabinet Table` (from searching "Furniture"), Item Specification `AUTOMATION_TEST-SPEC-FURN-001` (Draft→Submit record) and `AUTOMATION_TEST-SPEC-FURN-DRAFTMSG` (Draft-only record used purely to capture the verbatim Draft toast), Quantity `1`, Unit Price `25000` (total 25000 >= 20000 rule satisfied), Purchase Date and Registration Date both `20/09/2026`. Results: **Registration Number 757755** (Draft → Submit → PENDING, used for the Approve retry — see approval list catalog), **Registration Number 757756** (Draft only, left in DRAFT status, used only to capture the verbatim Draft success toast).
- Date pickers (`#registrationDate`, `#purchaseDate`, `#warrantyEndDate`) are read-only text inputs; they must be filled by opening the attached calendar icon button and clicking a day cell in the rendered `table` (`cell "<day>"`), not by typing.
- Toast messages are reliably read via `document.querySelectorAll('.toast-message, .toast, [class*=toast]')` immediately after the triggering click — they fade within a few seconds, so a `browser_evaluate` call right after the action (not a `find`/snapshot round-trip) is the reliable way to capture exact text.
- Measurement (`#mq`, 2026-10-03, read-only check, nothing added or saved): the box is an empty, editable number field for every item tried. Choosing the item sets the unit in `#uom` and does not fill the value: `Land-> Land-> Land-> Land` gives unit `Decimal` (group/category/sub-category all `Land`); `Cabinet Table` gives `Pcs`. The measurement is therefore typed in at registration (needed for Land and for any asset that will later be split). Evidence: `evidence/aaq_item_land_measurement.png`.
- Measurement carried through (2026-10-03): typing `12.5` in `#mq` for the Land item shows `12.5` with unit `Decimal` in the Asset Details grid after Add, the same value appears in the Approval List popup, and the approved asset's profile shows `12.50 Decimal`. Test record: registration `757793`, asset `BBDASR00227763` (item `Land-> Land-> Land-> Land`, project `[015] Microfinance (Dabi)`, quantity 1, unit price 25000). Evidence: `evidence/aaq_land_with_measurement.png`.
